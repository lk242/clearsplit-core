# ClearSplit 帳務計算規格

這份文件定義 MVP 必須遵守的帳務不變條件（accounting invariants）。任何 UI、匯入功能或未來後端都不得繞過這些規則。

## 1. 帳目是獨立計算單位

每筆支出以唯一的 `expenseId` 表示，包含：

- 原始金額
- 原付款人
- 分攤成員及其順序
- 日期與建立時間

每一筆還款義務都必須保留 `expenseId`，不得使用其他帳目的債權或債務抵銷。

## 2. 金額規則

- 幣別目前固定為 TWD。
- 金額必須是大於 0 的安全整數。
- 單筆輸入上限為 NT$ 99,999,999。
- 系統不使用浮點小數保存新台幣金額。

## 3. 平均分攤與餘數

基本份額為 `floor(金額 ÷ 人數)`。若無法整除，剩餘的 1 元依分攤名單順序逐一加入。

例如 NT$ 100 由 A、B、C 分攤：

| 成員 | 份額 |
|---|---:|
| A | NT$ 34 |
| B | NT$ 33 |
| C | NT$ 33 |

固定滿足：

```text
所有成員份額合計 ＝ 原始帳目金額
```

## 4. 還款義務

付款人的本人份額不會產生轉帳；其他分攤成員各自向原付款人支付自己的份額。

示範資料的完整結果：

### 週末聚餐 NT$ 1,860，阿哲先付

- 阿哲本人份額：NT$ 620
- 美玲 → 阿哲：NT$ 620
- 小宇 → 阿哲：NT$ 620

### 回程計程車 NT$ 540，美玲先付

- 美玲本人份額：NT$ 180
- 阿哲 → 美玲：NT$ 180
- 小宇 → 美玲：NT$ 180

以上四筆還款不會合併或互相抵銷。

## 5. 必須成立的不變條件

1. 每筆帳目的份額合計必須等於原始金額。
2. 每個還款義務必須指向一個存在的原始帳目。
3. 還款收款人必須是該帳目的原付款人。
4. 還款人必須是該帳目的分攤成員且不是原付款人。
5. 付款人、分攤成員與金額異常時，該帳目不得納入總計。
6. 成員被帳目引用時不得刪除。

## 6. 雲端帳本的控制層

正式雲端帳本以 Supabase/PostgreSQL 為權威資料源；LocalStorage 只保存目前裝置連到哪一本帳及介面偏好。資料庫層目前強制：

- 身分驗證、成員／負責人角色權限與資料列存取規則
- 建立者只作為不可變的來源稽核；目前負責人才是管理與財務權限主體
- 每個 LINE 帳號最多負責 5 本進行中／10 本總帳本，另可加入 30 本進行中帳本；每本最多 50 人
- 轉移負責人時以接收者配額為準，拒絕必須維持原權限不變
- 封存前必須完成私人與公費義務；封存後所有帳本子資料表由 trigger 強制唯讀
- 金額整數、份額守恆、外鍵與 optimistic version 併發控制
- 私人付款／收款、公費代墊／結清的雙向確認事件
- 財務資料變更的 audit event，以及 LINE webhook/event/message 冪等鍵
- 帳本封存與恢復另存 lifecycle event
- 後端 reconciliation：私人份額合計、公費成員餘額與總帳、公費交易分錄必須一致
- 負責人可下載同一資料庫快照產生的 JSON 備份與 CSV 對帳表

JSON 備份不包含 LINE user ID、邀請憑證、登入帳號 ID 或原始群組訊息。為避免覆寫正式帳與破壞稽核軌跡，網站不提供直接覆寫式還原；災難復原仍須搭配 Supabase 專案層級備份與還原政策。
